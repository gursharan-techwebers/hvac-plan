**For your architecture, I would not create 1,400 manually authored PSEO records.** But I also wouldn't blindly rely on only 50 state records.

The better approach is to separate **page identity/configuration** from **content/data**.

### Think of it like this

If you have:

* 50 states
* 5 tonnage options
* 5 SEER2 options

you technically have:

**50 × 5 × 5 = 1,250 URLs.**

But you don't need 1,250 copies of content.

---

## I recommend 50 state records + structured system/pricing data

### `States`

Create **50 records**:

```text
Arizona
Idaho
Texas
Florida
California
...
```

Each state contains genuinely local information:

```text
Arizona
├── labor index
├── permit information
├── climate
├── local cost factors
├── state-specific content
├── state-specific FAQs
└── state-specific sources
```

---

### `AC Systems`

Create your system combinations separately.

For example:

```text
3 ton / 14 SEER2
3 ton / 16 SEER2
3 ton / 18 SEER2

4 ton / 14 SEER2
4 ton / 16 SEER2
4 ton / 18 SEER2

5 ton / 14 SEER2
...
```

You might have 15–30 system records depending on the combinations you support.

---

### Then your URL is generated from the combination

```text
State
+
System
+
Pricing
+
Content
```

produces:

```text
/ac-cost-calculator/3-ton/16-seer2/arizona
```

and:

```text
/ac-cost-calculator/3-ton/16-seer2/idaho
```

etc.

# But what about unique PSEO content?

This is the important part.

Don't store this:

```text
PSEO Page #1
Arizona + 3 ton + 16 SEER2
full article...

PSEO Page #2
Arizona + 3 ton + 18 SEER2
same article...

PSEO Page #3
Arizona + 4 ton + 16 SEER2
same article...
```

That's exactly the type of structure I'd avoid.

Instead, create **content components that can be combined based on the data**.

For example:

### Arizona

```text
State Intro:
Arizona's hot and dry climate can affect...

Labor Content:
HVAC installation labor in Arizona...

Climate Content:
Air conditioners in Arizona typically...

Permit Content:
Permit requirements vary by Arizona municipality...
```

Then:

### 3-ton / 16-SEER2

```text
System Content:
A 3-ton 16-SEER2 system...
```

Your Next.js page combines them:

```text
Arizona content
+
3-ton content
+
16-SEER2 content
+
calculated pricing
+
relevant FAQs
+
sources
```

# Then where does the 1,400 come from?

**From your routing system, not from 1,400 manually maintained documents.**

For example:

```text
/ac-cost-calculator/
    3-ton/
        14-seer2/
            arizona
            idaho
            texas
            ...
        16-seer2/
            arizona
            idaho
            texas
            ...
        18-seer2/
            ...
```

Next.js understands the URL:

```text
3-ton
16-seer2
arizona
```

and queries Payload.

Conceptually:

```ts
const state = await getState("arizona");

const system = await getSystem({
  tonnage: 3,
  seer2: 16,
});

const pricing = calculatePrice({
  state,
  system,
});
```

Then:

```tsx
<PseoPage
  state={state}
  system={system}
  pricing={pricing}
/>
```

# However, there's one important exception

If a particular combination genuinely deserves **unique editorial content**, you can create a PSEO record for it.

For example:

```text
PSEO Override

Arizona
3 ton
16 SEER2

custom_intro:
...
custom_faq:
...
```

But that's an **override**, not the default architecture.

So you could have:

```text
1,400 URLs
        ↓
50 state records
+
20 system records
+
pricing rules
+
content blocks
+
FAQs
+
sources
        ↓
Next.js
        ↓
1,400 useful pages
```

And perhaps only:

```text
20–50 PSEO overrides
```

for particularly important combinations.

## This is actually better for Google too

The goal shouldn't be:

> "How do I make 1,400 pages look different?"

The goal should be:

> **"Why is each URL useful to someone searching for this exact combination?"**

For example:

**Arizona + 3-ton + 16-SEER2**

can have:

* Arizona-specific labor data
* Arizona permit considerations
* Arizona climate considerations
* actual calculated price
* 3-ton equipment information
* 16-SEER2 efficiency information
* Arizona-specific incentives where applicable
* relevant sources
* calculator
* contractor comparison CTA

That's substantially better than simply changing 5 words in a template.

### So my answer is:

**Don't create 1,400 PSEO records by default.**

Start with approximately:

```text
50 States
15–30 HVAC Systems
State-specific content
Pricing rules/data
Reusable FAQs
Sources
```

and let **Next.js generate the 1,400 URLs dynamically**.

That gives you a much more maintainable CMS and makes expanding later to furnaces, heat pumps, mini-splits, and contractor pages dramatically easier.
